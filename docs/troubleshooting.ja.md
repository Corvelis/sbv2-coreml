# トラブルシューティング

[ドキュメント一覧](README.ja.md) · [APIの仕様](api-reference.ja.md)

## まず記録すること

端末名、OS、SDK版、声名・モデルの版、入力文、`error.localizedDescription`、初回か2回目以降かを確認します。
性能の問題では、ロード／ウォームアップ／最初のPCM到着／合成全体／再生を分け、LLM・ASRとの同時実行と温度状態も記録してください。
ログには入力文やファイルパスが含まれる場合があります。共有時は不要な個人情報を取り除いてください。

## Xcodeでimportできない・ビルドできない

| 症状 | 確認・対処 |
|---|---|
| `No such module 'SBV2CoreML'` | `Package.swift`があるルートを追加し、ライブラリProductをアプリターゲットへリンクする |
| CocoaPodsやFlutterの設定を求められる | 独立配布の`Examples/Apple/SBV2Demo.xcodeproj`を開いているか確認。このSDKの導入にPodsは不要 |
| iOS／macOSのavailabilityエラー | Deployment TargetをiOS 18／macOS 15以上にする。Macの対象はApple Silicon |
| iPhoneへインストールできない | サンプルのTeam、Bundle Identifier、端末の開発設定を自分の環境へ合わせる |
| シミュレーターの速度が遅い | ANEとメモリの評価は実機で行う。シミュレーターのRTFを実機の指標にしない |

## モデルが見つからない・初期化に失敗する

`Model file not found`、`Core ML voice bundle is missing or invalid`などが出る場合：

1. `bert`には共通フォルダの**bertサブフォルダ**、`voice`には声フォルダの**ルート**、`dictionary`には辞書フォルダを指定する。
2. `config.json`、`style_vectors.npy`、`coreml_voice/voice_shared.mlpackage`が同じ声のパッケージ内に揃っているか確認する。
3. `.mlpackage`の内部にある重みファイルまでコピーされているか確認する。Git LFSのポインターテキストだけを取得していないかも確認する。
4. ZIP／tar.gz／AIVMをそのままロードしていないか確認する。SDKがロードするのは展開済みCore ML形式。
5. iCloud等のファイルがすべてローカルに取得済みか確認する。
6. 配布ファイルのハッシュを`sbv2-coreml verify`で検証する。[コマンドの準備](conversion.ja.md)

`Open JTalk dictionary could not be loaded`なら、`sys.dic`だけでなく、配布した辞書フォルダ全体を配置します。
`VoiceInfo`が読めるだけでは、モデル本体を読み込めることの確認にはなりません。

## キャッシュを保存できない

`persist compiled cache failed`などが出る場合は、モデルと同じ階層に書き込めるか、空き容量があるか確認します。
現在のBERTローダーは隣接する`.mlmodelc`へ保存する必要があります。
アプリBundleや読み取り専用の共有先を直接使わず、Documents／Application Supportへモデル全体をコピーします。
外部フォルダには[セキュリティスコープの管理](sdk-guide.ja.md)も必要です。

端末・OS変更後などにキャッシュが壊れた疑いがある場合は、合成を止めて`unload`を待ち、
対象モデルの`.mlmodelc`だけを削除して再ロードします。`.mlpackage`、辞書、スタイルベクトルは残します。
再コンパイルが必要になるので、正常なキャッシュを毎回削除しないでください。

## モデルをロードしたのに最初だけ遅い

`load`と初回の推論準備は別です。ロード後、実際に使う話者・スタイルを指定して`warmUp`を待ってください。
現在の`warmUp`は短い挨拶を1回合成するため、別の長さの初回入力には追加の準備が発生し得ます。
発話ごとに`SpeechSynthesizer()`や`load`を作り直さず、会話中は同じインスタンスを保持します。
モデルを取得済みでも、再起動後のロード時間までゼロになるものではありません。

## RTFが変動する

- 速度の比較には最適化されたReleaseビルドを使い、デバッガを外して同じ端末で測ります。
- 短い音声は分母が小さく、固定の準備時間の影響が大きくなります。
- 文章・スタイルによって予測音声長や使う形状が変わります。
- 熱、低電力状態、LLM・ASR・他の処理との競合も比較条件に含めます。
- `decoder_validation.json`を確認します。精度検証によってFP32へ切り替えた声は、混合精度の声より遅くなる場合があります。
- `SpeechChunk.rtf`は成功した合成処理の指標です。ロード・待機・再分割の失敗試行を含む総時間は別に測ります。

同じ文章、同じスタイル、同じウォームアップ条件で比べてください。

## 句読点以外で分かれる・音声の続きが途切れる

**文章の分割**と**再生キューの不足**を別々に調べます。

- `chunk.text`と`capacitySplit`を記録する。`stream`の既定は句点／改行、最初だけ読点、強制上限250文字。`synthesize`は隣接する文を250文字以内でまとめる。
- 128音素／512フレームなどのモデル容量を超えると追加分割される。250文字まで必ず一括合成できる意味ではない。
- LLMから区間ごとに別の`stream`を作る場合、読点の「最初」の判定も毎回始まる。2区間目以降は`allowFirstComma: false`を選ぶ。
- 再生が終わってから次の合成を始めず、残り時間を見て前もって要求する。付属サンプルは全文を生成してから一括再生するため、この補充処理は使わない。
- 再生残量と合成時間を記録し、必要なら合成開始を早める。LLMを一時待機する制御はアプリ側で接続する。
- PCMを16 bitとして読んでいないか確認する。`pcm`はFloat32、`wav()`の出力は16 bit WAV。

SDKの追加分割はテキストを捨てる処理ではありません。特定の音節が消えるなどの再現例は、入力文、声の版、区間情報とともに報告してください。

## スタイルが選べない・音が出ない

`Invalid speaker, style or speed`なら`VoiceInfo`に含まれる名前とIDを使います。`Neutral`という名前がない声もあります。
空白だけのテキストは空PCMになります。`duration`と`pcm.count`を確認してください。
PCMができているのに無音なら、音量、出力先、再生プレイヤー、AVAudioSessionを確認します。SDK単体では再生しません。

## 止めたのに音声が続く

合成Taskのキャンセル、`speech.cancel()`、プレイヤー停止を組み合わせます。
既に再生キューへ渡したPCMはSDK側のキャンセルだけでは取り消せません。
処理中のCore ML呼び出しは完了を待つため、その間に開始した次の操作へ古い結果を反映しないようにします。

## RAM・ストレージが増える

| 種類 | 管理方法 |
|---|---|
| モデルのRAM | 通常は1インスタンスを保持。不要になったら`unload`。共有辞書・OSキャッシュが残る可能性あり |
| 合成PCM | 長文は`stream`を使い、再生キューを制限。再生済みバッファを解放 |
| 共通BERT・辞書 | 声ごとにコピーせず、1組を共有。配布ファイルで約1.52 GB |
| 声モデル | JVNVサンプルは約294 MB。不要な声は停止・解放後にアプリ側で削除 |
| `.mlmodelc` | 端末上のコンパイルキャッシュ。削除できるが、次回再生成が必要 |
| Macの変換作業 | ダウンロード元、Python環境、変換中モデル、配布アーカイブを区別して整理 |

声モデルの精度や構造によってモデル容量が変わり、RAM使用量は機種・文章・精度設定によって変わります。
メモリ比較ではphysical footprint、residentなど、同じ指標を使ってください。
変換CLIは一時出力を終了時に片付けます。`--cache`で指定したダウンロードキャッシュや完成モデルは残ります。

## 変換・ダウンロードのエラー

| メッセージ／症状 | 対処 |
|---|---|
| `AIVMX alone is unsupported` | 原本のAIVM／Safetensorsを用意する。AIVMXは直接の入力対象外 |
| `Unsupported architecture` | JP-Extraの対応構造か確認。[モデル仕様](model-format.ja.md)へ |
| `Output already exists` / `Destination already exists` | 別の新しい出力先を指定。既存モデルへ上書きするコマンドではない |
| `Required checkpoint tensor is missing` | 不完全な学習出力や異なる構造を疑う。欠けた重みをランダムに補って変換しない |
| FP32検証も失敗する | 検証を無効化せず、原本・設定・変換環境とログを確認する |
| `Checksum or download failed` | 配布URL・版・空き容量・接続を確認。Webページではなく`download.json`を渡す |
| 配布用packageがライセンス不足で止まる | 原本の実際のライセンス文とID・出典を指定して変換する。任意の許諾を推測して付けない |
